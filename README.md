# Denois-Implementation# DenOiS implementation and comparison with physics-based speed-of-sound reconstruction

This repository contains my re-implementation of **DenOiS** (Bezek & Goksel, 2026), a learning-based method for imaging the speed of sound (SoS) in tissue from ordinary pulse-echo ultrasound. I compare it against the two physics-based methods from H. Meng's MSc thesis (Uppsala University, 2026): **DAS+CMPE** and **SSFM**. All three methods are evaluated on the same public data.

The whole pipeline runs in about 100 minutes on a free Kaggle session with 2× T4 GPUs.

> This is a student project, not an official implementation of any of the three methods. DenOiS has no public code, so everything here is written from the paper, and several parts had to be scaled down to fit free GPUs (see [Limitations](#limitations)).

---

## Why speed-of-sound imaging?

Ultrasound scanners assume that sound travels at 1540 m/s everywhere in the body. It doesn't: fat is slower (about 1450 m/s), and muscle and liver are faster (about 1580 m/s). A map of the true speed of sound is useful for two reasons:

- it is a **quantitative tissue marker**, for example for fatty liver or breast density;
- it allows **sharper B-mode images**, because the scanner can correct its timing.

The difficulty is that the probe sees the body from one side only, so many different speed maps explain the recorded echoes almost equally well.

## The three methods

| | DenOiS | DAS+CMPE | SSFM |
|---|---|---|---|
| Idea | Measure echo delays between steered transmits, clean them with a network, reconstruct with a diffusion model | Put the SoS map inside the beamformer and make images from different parts of the probe agree | Simulate the waves through the SoS map and maximise how sharply the echoes focus |
| Physics model | straight rays | straight rays | full-wave (split-step Fourier) |
| Needs training data | yes (simulated) | no | no |
| Paper | Bezek & Goksel 2026, [arXiv:2604.02105](https://arxiv.org/abs/2604.02105) | Simson et al. 2023/2026; Meng 2026 | Meng 2026 |

## Data

Everything is evaluated on the public **IMPACT** release (Ali et al., IEEE TCI 2023, [github.com/rehmanali1994/IMPACT](https://github.com/rehmanali1994/IMPACT)). The notebook downloads it automatically, about 1.7 GB.

| Case | Type | Ground truth |
|---|---|---|
| AbdominalMap3, AbdominalMap4 | k-Wave simulation of an abdominal wall | yes |
| PhantomL12-5-50mm | real phantom | no |
| RatAbdomenL12-3v | real in-vivo rat | no |

The DenOiS networks are **trained only on synthetic data** generated by this code: 3000 ray-model cases and 300 cases from my own wave simulator. They never see the IMPACT data during training.

## Main results

RMSE in m/s against the ground truth on the two abdominal cases (lower is better):

| Method | Abdominal 3 | Abdominal 4 | Mean |
|---|---|---|---|
| **DAS+CMPE** | **31.3** | **23.5** | **27.4** |
| Constant 1540 m/s (no reconstruction) | 33.9 | 27.3 | 30.6 |
| DenOiS R_D (raw delays) | 33.2 | 29.6 | 31.4 |
| L1-TV | 32.6 | 30.5 | 31.6 |
| SSFM (subsampled to fit a T4) | 32.7 | 39.1 | 35.9 |
| DenOiS R_D with refined delays | 49.8 | 39.0 | 44.4 |

Main findings:

1. **DenOiS's key idea works on inclusions.** On simulated media with circular and rectangular inclusions, refining the delays before reconstruction cuts the L1-TV error from 29.1 to 18.2 m/s, and the contrast error from 38.4 to 22.4 m/s.
2. **The diffusion reconstruction did not beat plain TV** with my much smaller training budget (3k cases and 20–40 epochs, against 10k cases and 400 epochs in the paper).
3. **On the layered abdomen, only DAS+CMPE beats a constant guess**, and it matches the numbers reported in the thesis.
4. **Why the delay-based methods fail there.** Horizontal layers barely show up in the inter-transmit delays: about 3% of the signal amplitude at ±16° steering. Even a reconstruction from *perfect* delays only reaches 29.6 m/s RMSE on Abdominal 3, against 33.9 for doing nothing. This is a limit of the measurement, not of any network.
5. **SSFM finds the layered structure but is too noisy at the data rate I could afford** (1/16 of the frequencies, 1/4 of the transmits). It doesn't reach the thesis accuracy.

## How to run

### On Kaggle (easiest)

1. Upload `notebooks/sos_denois_vs_thesis.ipynb` (File → Import Notebook).
2. Set **Accelerator: GPU T4 ×2** and **Internet: On**.
3. Click **Save Version → Save & Run All**. The run downloads the data, generates datasets, trains, evaluates and builds the comparison in about 100 minutes.

Set `MODE = 'quick'` in the config cell for a ~20-minute check that everything runs. Its numbers are not meaningful.

### On your own machine

You need Python 3.10+ and a CUDA GPU with at least 12 GB of memory.

```bash
git clone https://github.com/DiyanshuKundu/Denois-Implementation.git
cd Denois-Implementation
pip install -r requirements.txt

# download the IMPACT data and run a quick test
python -c "from sosbench.acq import download_impact; download_impact()"
python -c "from sosbench.smoke import run_smoke; run_smoke('impact_data')"

# see all commands
python -m sosbench.cli --help
```

For example, to run only DAS+CMPE on Abdominal 3:

```bash
python -m sosbench.cli thesis --method das --name abd3 --root impact_data --out results_thesis --iters 150
```

The notebook contains its own copy of the code. If you change anything in `sosbench/`, run `python notebooks/build_merged.py` to update it.

## Limitations

- **Small training budget.** DenOiS was trained on about a third of the paper's data and about 10% of its epochs. The diffusion parts (R_D, the M_D refiner and the DOLCE baseline) suffer most from this.
- **Own simulator instead of k-Wave** for the training data. It matches k-Wave reasonably well (correlation of the delays 0.56–0.72) but isn't identical.
- **SSFM is subsampled** to fit a T4. The full-data version should be closer to the thesis results.
- **The direct U-Net baseline (Unet[5]) did not train properly** in the final run (NaN losses), so its numbers should be ignored.
- **The thesis methods use the settings from the thesis**, which were likely tuned on the same abdominal cases.
- Only two test cases have ground truth on realistic data, so the abdominal numbers come from a very small sample.
